## 1.以下数组，isTop为true的先排前面，然后再对时间进行倒序

```javascript
let a = [
  {
    id: 1,
    isTop:true,
    time:'2024-10-01',
  },
  {
    id: 2,
    isTop:false,
    time:'2024-10-02',
  },
  {
    id: 3,
    isTop:true,
    time:'2024-10-08',
  },
  {
    id: 4,
    isTop:false,
    time:'2024-10-04',
  },
  {
    id: 5,
    isTop:false,
    time:'2024-10-09',
  },
]

let b = a.sort((value1, value2) => {
  if (value1.isTop && !value2.isTop) {
    // 此时value1要在前，value2在后 value1-value2<0
    return -1
  } else if (!value1.isTop && value2.isTop) {
    // value2在前，value1在后 valu1-value2>0
    return 1
  } else {
    return new Date(value2.time) - new Date(value1.time)
  }
})
```

## 2.前端项目重新打包部署后如何通知用户更新

### 1. 使用 Service Worker 和 Cache

如果你的项目使用了 Service Worker 和缓存策略，可以通过检测 Service Worker 的更新来通知用户。

#### 示例代码：

```javascript
if ('serviceWorker' in navigator) {
  window.addEventListener('load', () => {
    navigator.serviceWorker.register('/service-worker.js').then(registration => {
      registration.addEventListener('updatefound', () => {
        const installingWorker = registration.installing;
        installingWorker.addEventListener('statechange', () => {
          if (installingWorker.state === 'installed') {
            if (navigator.serviceWorker.controller) {
              // 新的 Service Worker 已经安装，提示用户刷新页面
              showUpdateNotification();
            } else {
              // 没有旧的 Service Worker，首次安装
            }
          }
        });
      });
    });

    // 检查更新
    setInterval(() => {
      navigator.serviceWorker.getRegistration().then(registration => {
        if (registration && registration.waiting) {
          showUpdateNotification();
        }
      });
    }, 60 * 1000); // 每分钟检查一次
  });
}

function showUpdateNotification() {
  const notification = document.createElement('div');
  notification.className = 'update-notification';
  notification.innerHTML = `
    <p>新版本已可用，请刷新页面以获取最新内容。</p>
    <button id="refresh-btn">刷新页面</button>
  `;
  document.body.appendChild(notification);

  document.getElementById('refresh-btn').addEventListener('click', () => {
    window.location.reload();
  });
}
```

### 2. 使用版本号检查

1. **创建版本号文件**： 在项目中创建一个 `version.txt` 文件，并在每次部署时更新其内容。

   ```
   version.txt
   1.0.1
   ```

2. **前端代码检查版本号**： 在前端代码中定期检查 `version.txt` 文件，与本地存储的版本号进行比较，如果版本号不同，则提示用户更新。

#### 示例代码：

```javascript
const VERSION_URL = '/version.txt';

async function checkForUpdates() {
  try {
    const response = await fetch(VERSION_URL);
    const newVersion = await response.text();
    const currentVersion = localStorage.getItem('appVersion');

    if (newVersion !== currentVersion) {
      showUpdateNotification();
      localStorage.setItem('appVersion', newVersion);
    }
  } catch (error) {
    console.error('Error checking for updates:', error);
  }
}

function showUpdateNotification() {
  const notification = document.createElement('div');
  notification.className = 'update-notification';
  notification.innerHTML = `
    <p>新版本已可用，请刷新页面以获取最新内容。</p>
    <button id="refresh-btn">刷新页面</button>
  `;
  document.body.appendChild(notification);

  document.getElementById('refresh-btn').addEventListener('click', () => {
    window.location.reload();
  });
}

// 定期检查更新
setInterval(checkForUpdates, 60 * 1000); // 每分钟检查一次

// 初始检查
checkForUpdates();
```

## 3.setTimeout 和 setInterval 的倒计时误差

在 JavaScript 中，`setTimeout` 和 `setInterval` 是常用的定时器函数，但它们存在时间偏差的问题。以下是导致这种误差的主要原因：

1. **事件循环机制**：
   - JavaScript 是单线程的，所有任务（包括定时器回调）都在一个事件循环中执行。
   - 当事件循环中有其他任务正在执行时，定时器回调会被推迟到当前任务完成后才执行。这会导致实际执行时间比预期时间晚。
2. **浏览器性能限制**：
   - 浏览器可能会因为性能问题（如高负载、垃圾回收等）而延迟执行定时器回调。
   - 在某些情况下，浏览器会将多个 `setInterval` 回调合并为一次执行，以减少 CPU 使用率。
3. **系统时间调整**：
   - 如果用户手动调整了系统时间，或者系统时间因 NTP 同步而发生变化，定时器的时间计算也会受到影响。

### 解决方案

为了减小或消除这些误差，可以采用以下几种方法：

#### 1. 使用 `requestAnimationFrame`

`requestAnimationFrame` 是浏览器提供的高精度定时器，它会在每一帧渲染之前执行回调函数。这种方式可以确保回调函数在页面渲染时得到执行，从而减小时间偏差。

```
javascriptfunction countdownWithRAF(targetDate) {
  const now = new Date().getTime();
  const difference = targetDate - now;
  const remainingTime = {
    days: Math.floor(difference / (1000 * 60 * 60 * 24)),
    hours: Math.floor((difference % (1000 * 60 * 60 * 24)) / (1000 * 60 * 60)),
    minutes: Math.floor((difference % (1000 * 60 * 60)) / (1000 * 60)),
    seconds: Math.floor((difference % (1000 * 60)) / 1000),
  };

  // 更新倒计时显示
  updateCountdownDisplay(remainingTime);

  if (difference > 0) {
    requestAnimationFrame(() => countdownWithRAF(targetDate));
  }
}

const targetDate = new Date('2023-12-31').getTime();
countdownWithRAF(targetDate);
```

#### 2. 使用 `performance.now()`

`performance.now()` 提供了更高精度的时间测量，适用于需要精确时间间隔的场景。通过结合 `performance.now()` 和 `setTimeout` 或 `setInterval`，可以更准确地控制定时器的执行时间。

```
javascriptlet startTime = performance.now();

function countdownWithPerformanceNow(targetDate) {
  const now = performance.now();
  const elapsed = now - startTime;
  const difference = targetDate - elapsed;

  const remainingTime = {
    days: Math.floor(difference / (1000 * 60 * 60 * 24)),
    hours: Math.floor((difference % (1000 * 60 * 60 * 24)) / (1000 * 60 * 60)),
    minutes: Math.floor((difference % (1000 * 60 * 60)) / (1000 * 60)),
    seconds: Math.floor((difference % (1000 * 60)) / 1000),
  };

  // 更新倒计时显示
  updateCountdownDisplay(remainingTime);

  if (difference > 0) {
    setTimeout(() => countdownWithPerformanceNow(targetDate), 1000);
  }
}

const targetDate = new Date('2023-12-31').getTime();
startTime = performance.now();
countdownWithPerformanceNow(targetDate);
```

#### 3. 动态调整定时器间隔

通过动态调整 `setTimeout` 或 `setInterval` 的间隔时间，可以补偿由于任务队列延迟导致的时间偏差。每次回调时重新计算剩余时间，并根据剩余时间调整下一次回调的时间间隔。

```
javascriptfunction countdownWithDynamicInterval(targetDate) {
  const now = new Date().getTime();
  const difference = targetDate - now;

  const remainingTime = {
    days: Math.floor(difference / (1000 * 60 * 60 * 24)),
    hours: Math.floor((difference % (1000 * 60 * 60 * 24)) / (1000 * 60 * 60)),
    minutes: Math.floor((difference % (1000 * 60 * 60)) / (1000 * 60)),
    seconds: Math.floor((difference % (1000 * 60)) / 1000),
  };

  // 更新倒计时显示
  updateCountdownDisplay(remainingTime);

  if (difference > 0) {
    const interval = Math.min(difference, 1000); // 确保最后一次回调尽可能接近目标时间
    setTimeout(() => countdownWithDynamicInterval(targetDate), interval);
  }
}

const targetDate = new Date('2023-12-31').getTime();
countdownWithDynamicInterval(targetDate);
```

### 总结

`setTimeout` 和 `setInterval` 的时间偏差问题是由于 JavaScript 的单线程事件循环机制和浏览器性能限制引起的。通过使用 `requestAnimationFrame`、`performance.now()` 或动态调整定时器间隔，可以有效减小或消除这些误差，确保倒计时功能的准确性。

## 4.写个异步调度函数，参数是一堆异步任务数组，怎么快速执行完这些函数，又不会阻塞浏览器渲染

为了快速执行一堆异步任务，同时避免阻塞浏览器渲染，可以使用 `requestAnimationFrame` 来分批处理任务。这样可以在浏览器的每一帧中处理一部分任务，从而避免长时间占用主线程导致的卡顿。

以下是一个示例实现：

```javascript
async function asyncScheduler(tasks: (() => Promise<void>)[]): Promise<void> {
  let index = 0;

  return new Promise((resolve) => {
    function runBatch() {
      const startTime = performance.now();
      while (index < tasks.length && performance.now() - startTime < 16) { // 16ms is approximately 60fps
        tasks[index]().then(() => {
          index++;
          if (index === tasks.length) {
            resolve();
          }
        });
        index++;
      }

      if (index < tasks.length) {
        requestAnimationFrame(runBatch);
      } else {
        resolve();
      }
    }

    requestAnimationFrame(runBatch);
  });
}

// 使用示例
const tasks = [
  async () => { /* 异步任务1 */ },
  async () => { /* 异步任务2 */ },
  // 更多任务...
];

asyncScheduler(tasks).then(() => {
  console.log('所有任务完成');
});
```

### 解释

1. **`asyncScheduler` 函数**：接受一个异步任务数组 `tasks`。
2. **`runBatch` 函数**：在每一帧中处理一部分任务，直到用尽 16ms（大约 60fps 的一帧时间）。
3. **`requestAnimationFrame`**：用于在浏览器的每一帧中执行 `runBatch` 函数，确保任务不会阻塞浏览器渲染。
4. **`performance.now()`**：用于测量每一帧中已经花费的时间，确保不超过 16ms。
5. **`resolve`**：当所有任务完成后，调用 `resolve` 来结束 `asyncScheduler` 的 Promise。

这种方法可以有效地分批处理异步任务，避免长时间占用主线程，从而保持良好的用户体验。

## 5.写个同步调度函数，参数是一堆同步任务数组，怎么快速执行完这些函数，又不会阻塞浏览器渲染

在 JavaScript 中，同步任务会阻塞浏览器的渲染线程，因此直接执行大量的同步任务会导致界面卡顿。为了在不阻塞浏览器渲染的情况下执行同步任务，可以使用 `requestAnimationFrame` 或 `setTimeout` 来分批处理任务。

下面是一个使用 `requestAnimationFrame` 的示例，它将同步任务分批执行，确保每一帧中只处理一部分任务，从而避免阻塞渲染线程。

### 示例代码

```javascript
function syncScheduler(tasks: (() => void)[]): void {
  let index = 0;

  function runBatch() {
    const startTime = performance.now();
    while (index < tasks.length && performance.now() - startTime < 16) { // 16ms is approximately 60fps
      tasks[index]();
      index++;
    }

    if (index < tasks.length) {
      requestAnimationFrame(runBatch);
    }
  }

  requestAnimationFrame(runBatch);
}

// 使用示例
const tasks = [
  () => { /* 同步任务1 */ },
  () => { /* 同步任务2 */ },
  // 更多任务...
];

syncScheduler(tasks);
```

### 解释

1. **`syncScheduler` 函数**：接受一个同步任务数组 `tasks`。
2. **`runBatch` 函数**：在每一帧中处理一部分任务，直到用尽 16ms（大约 60fps 的一帧时间）。
3. **`requestAnimationFrame`**：用于在浏览器的每一帧中执行 `runBatch` 函数，确保任务不会阻塞浏览器渲染。
4. **`performance.now()`**：用于测量每一帧中已经花费的时间，确保不超过 16ms。
5. **`index`**：用于跟踪当前处理到的任务索引。

这种方法可以有效地分批处理同步任务，避免长时间占用主线程，从而保持良好的用户体验。

### 注意事项

- **任务复杂度**：如果单个任务的执行时间较长，可能需要进一步优化任务的粒度。
- **任务依赖**：确保任务之间没有依赖关系，否则分批执行可能导致不可预测的行为。

通过这种方式，可以有效地管理大量同步任务的执行，同时保持界面的流畅性。

## 6.将数字每千分位用逗号隔开

**数字有小数版本：**

```javascript
let format = n => {
    let num = n.toString() // 转成字符串
    let decimals = ''
        // 判断是否有小数
    num.indexOf('.') > -1 ? decimals = num.split('.')[1] : decimals
    let len = num.length
    if (len <= 3) {
        return num
    } else {
        let temp = ''
        let remainder = len % 3
        decimals ? temp = '.' + decimals : temp
        if (remainder > 0) { // 不是3的整数倍
            return num.slice(0, remainder) + ',' + num.slice(remainder, len).match(/\d{3}/g).join(',') + temp
        } else { // 是3的整数倍
            return num.slice(0, len).match(/\d{3}/g).join(',') + temp 
        }
    }
}
format(12323.33)  // '12,323.33'
```
