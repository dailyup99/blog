## 2.uniapp中封装接口请求相较于微信小程序有什么要注意的

uniapp和微信小程序都提供了网络请求API（uni.request(object)）和wx.request(object)，但uniapp为了实现跨端兼容，需要注意网络请求跨域问题，微信小程序不用考虑多端兼容，也不会出现跨域问题。

uniapp中的跨域问题依然可以通过在vue.config.js中配置Proxy代理解决：

devServer=>Proxy=>changeOrigin: true // 是否跨域

## 3.uniapp页面路由都有哪些方式？有什么区别？

uniapp有两种页面路由跳转方式：

* 使用navigator组件跳转
* 调用API跳转
  * navigateTo：保留当前页面，跳转到应用内某个页面，使用uni.navigateBack可以返回原页面
  * redirectTo：关闭当前页面，跳转到应用内某个页面
  * navigateBack：返回原页面
  * switchTab：跳转到tabBar页面，并关闭其他所有非tabBar页面
  * reLaunch：关闭所有页面，打开应用内某个页面

## 4.uniapp页面间怎么进行通讯？

**方式一：url查询字符串和EventChannel**

从A页面跳转到B页面

A页面传递参数：一个url中的问号后面的查询字符串；另一个是通过eventChannel传递的数据

```javascript
goToB() {
    uni.navigateTo({
        url: "/pages/pageB/pageB?name=abc&id=100",
        success(res) {
            // 通过eventChannel向被打开页面传送数据
            res.eventChannel.emit('acceptDataFromA', { 
                data: '我是从A页面传递过来的数据' ,
            })
        }
    })
}
```

B页面接收

在onLoad生命周期里面接收

options接收url传递过来的参数，使用getOpenerEventChannel接收eventChannel传递过来的参数

```javascript
onLoad(options) {
			console.log('接受url传递过来的数据:', options);
            const eventChannel = this.getOpenerEventChannel();
            eventChannel.on("acceptDataFromA", (data) => {
                console.log("接收到eventChannel的参数：", data)
            })
		},
```

**方式二：事件总线 **

从A跳到B，再从B返回A，通过事件总线传递数据给A

B页面

```javascript
uni.$emit('acceptDataFromB', {
					data: {
						desc: '这是在B传递到A页面的数据'
					}
				})
```

A页面

```javascript
onLoad() {
    // 通过事件总线在拿到B传递回来的数据
    uni.$on('acceptDataFromB', this.acceptDataFromB)	
},
onUnload() {
    uni.$off('acceptDataFromB', this.acceptDataFromB)
},
```

## 5.uniapp中的生命周期

**应用生命周期**

* onLaunch：初始化完成时触发（全局只触发一次）
* onShow：uniapp启动，从后台进入前台显示
* onHide：从前台进入后台
* onError：uniapp报错时显示
* onExit：监听应用退出

**页面生命周期**

* onLoad（options）：监听页面加载
* onShow：监听页面显示
* onReady：监听页面初次渲染完成
* onHide：监听页面隐藏
* onUnload：监听页面卸载
* onPullDownRefresh：监听用户下拉动作，一般用于下拉刷新
* onReachBottom：页面滚动到底部的事件，常用语下拉下一页数据

## 6.微信小程序是怎么打包的？

* 注册一个微信小程序账号
* 登录已经注册好的账号，拿到小程序的appId
* 修改mainfest.json的配置（比如appId，es6转es5、上传代码时样式自动补全、上传代码时自动压缩）
* 发行=>小程序-微信，有个弹窗，填写应用名称和appId
* 微信开发者工具，微信公众平台配置域名，然后点击上传，填写版本号和项目备注
* 在微信小程序后台的版本管理，开发版本就有个体验版的二维码，可以扫码进行体验，给测试使用
* 测试没有问题了，提交审核到审核版本，审核通过就可以发布上线

## 8.Android或IOS云打包怎么配置？

* 注册一个Dcloud账号
* HBuilder X登录已注册号的账号，然后在mainfest.json中配置基本应用信息，比如配置App图标等
* 发行=>原生App-云打包
* 就会有个弹窗，打Android包和IOS包可以切换
  * 填写安卓包名，使用的是自有证书（好处是可以修改，如果选择云端证书自动生成就不能修改），然后填写证书别名，证书私钥密码，选择证书文件
  * 如果是打IOS包，需要填写证书私钥密码，选择证书profile文件和选择私钥证书
  * 这些由公司提供
* 打包好之后在unpackage/release/apk目录下有个.apk的文件，把这个apk发给运维

## 9.uniapp的分包有了解过吗？

为什么要分包呢？

因为小程序有体积和资源加载限制（微信小程序每个分包的大小是2M，总体积一共不能超过20M），使用分包可以优化小程序的下载和启动速度。

分包步骤

首先在 mainfest.json mp-weixin添加以下代码（启动分包）

```javascript
"optimization": {
    "subPackages": true
}
```

接着在pages.json中进行配置subPackages，它是个数组，数组每一项都是应用的子包。属性值主要有：

* root：子包的根目录
* pages：子包由哪些页面组成

在小程序启动时，默认会下载主包并启动主包内页面，当用户进入分包内某个页面时，会把对应分包自动下载下来，下载完成后再进行展示。

注意事项：

* tabbar栏的内容不能进行分包

* 分包下支持独立的static目录，用来对静态资源进行分包
* 针对vendor.js过大的情况可以运行时压缩代码
  * `HBuilderX`创建的项目勾选`运行-->运行到小程序模拟器-->运行时是否压缩代码`
* 可以在微信开发者工具中的详情查看代码依赖分析，看看是否需要分包

## 10.小程序支付如何实现？

1.小程序注册，要以公司的身份去注册一个小程序，才有微信支付权限

2.绑定商户号

3.在小程序填写合法域名

具体做法：

* 打开某小程序，点击直接下单

* 调用wx.login()获取用户临时登录凭证code，发送到后端服务器换取openId
* 下单时，调接口，传参数：商品id，数量还有openId
* 后端返回一些必要信息，这些信息在调wx.requestPayment()发起微信支付的时候要用到

```javascript
wx.requestPayment({
  // 时间戳
  timeStamp: '',
  // 随机字符串
  nonceStr: '',
  // 统一下单接口返回的 prepay_id 参数值
  package: '',
  // 签名类型
  signType: '',
  // 签名
  paySign: '',
  // 调用成功回调
  success () {},
  // 失败回调
  fail () {},
  // 接口调用结束回调
  complete () {}
})
```

一般在success回调中跳转到支付结果页。

## 11.说下小程序的架构模型

**谁是小程序的宿主环境呢？微信客户端**

宿主环境为了执行小程序的各种文件：wxml文件、wxss文件、js文件

**当小程序基于WebView环境下时，WebView的 JS逻辑、DOM树创建、CSS解析、样式计算、Layout、Paint (Composite)都发生**

**在同一线程，在** **WebView** **上执行过多的** **JS** **逻辑可能阻塞渲染，导致界面卡顿。**

**以此为前提，小程序同时考虑了性能与安全，采用了目前称为「双线程模型」的架构。**

**双线程模型：**

WXML模块和WXSS样式运行于 渲染层，渲染层使用WebView线程渲染（一个程序有多个页面，会使用多个WebView的线程）。

JS脚本（app.js/home.js等）运行于 逻辑层，逻辑层使用JsCore运行JS脚本。

这两个线程都会经由微信客户端（Native）进行中转交互。
